可信数据、受控 Agent 与评测回归

以砚舟智造的 30 席试点为例，从会话中的人工接管请求出发，核对客户联系偏好和交付范围，再查看 Agent 给出的带依据的回访建议。另有区域团队扩容、订阅续签和安全评审等示例。

本页介绍完整产品的设计要点。演示站按真实结构搭建，使用虚构数据，纯静态运行，不会调用真实模型，也不会对外发送消息。

要解决什么问题

销售跟进企业试点或席位扩容时，需要核对 WhatsApp 会话、CRM 商机记录，以及内部产品和报价政策。资料分散时容易漏掉客户偏好或引用旧政策。涉及价格承诺和对客沟通时，由负责人核对后确认。

系统的做法是：销售选定客户范围后，由 Agent 读取已经确认的记忆与产品依据，协作分析商机，并产出带来源、缺失材料和下一步建议的报告。负责人可以补充方向并接续任务；对客动作必须经过独立确认。执行轨迹和分层评测用来定位事实遗漏、协作冲突和输出失败，为后续修正资料、工具或流程提供依据。

系统设计架构全景

将业务交互、受控 Agent Harness、三源分离的可信数据面与评测回归明确划界：记忆与知识摘要仅作参考，数据库始终保持唯一事实真源，对客与高敏操作必须过提案人审。

持久化 Run 与动作提案状态机

模型单回合结束只是中间态。异步队列、租约校验、6 字段带快照可逆写、人审挂起续跑与写回不确定停机共同保证长任务可控收敛。

核心能力

MCP 工具治理与 Ontology

商机、会话与知识工具复用领域 Handler，按可信租户、角色、范围及白名单授权。Ontology 使用版本化口径、许可查询模板和受限只读角色查库并返回查询依据。

客户长期记忆与可信召回

PostgreSQL 保存已确认的客户偏好。查询时并行走本地 BM25 和 Mem0 语义召回，回读 SQL 核对归属、内容哈希及有效性，再保留锁定项并以 RRF 融合。Mem0 失败时降级本地。

企业知识与引用溯源

本地 pgvector 与 WeKnora 企业 Wiki 按授权范围提供资料。发布原页、来源版本和哈希进入引用校验，复用前再次验证，已失效引用停止展示。

Pi Runtime 与持久编排

Pi 运行多轮模型与工具，Harness 管理动作权限和结构化交付。PostgreSQL 队列与 Worker 承担租约校验和恢复，Run 行锁为运行事件分配序号，支持流式回放。

多 Agent 与证据冲突治理

Supervisor 汇总多个只读 Specialist 的观察，按字段值与来源版本比对。发现相关证据不一致时暂停对应写入，并记录待人工确认或重读的差异。

Langfuse 与分层评测

Trace 经白名单脱敏后通过 Outbox 异步投递。确定性规则核对事实、权限和引用，语义 Judge 检查任务贴合度与可执行性。固定回归样本覆盖已确认的失败模式。

人机协同与安全边界

  • 对客动作先提案、后确认 推进商机阶段和对客户发送消息等动作，由 Agent 生成提案，在工作台交给有权限的负责人确认。
  • 白名单写入与一键撤销 Agent 仅可自动修改 6 个低敏感辅助字段，写入前保存快照。人工撤销时会比对是否已被销售改过，避免覆盖最新的人工修改。
  • 策略版本与紧急熔断 主管调整跟进策略时会生成新版本，并终止旧草稿的继续执行。必要时可按全租户或单个客户立即阻断尚未发出的对客动作。
  • 审批防重与并发保护 批准、拒绝和暂停在重试时复用同一请求键，避免网络抖动导致重复执行；长耗时写入还会校验队列租约，拦截超时旧进程的迟到写回。

界面与工程

  • 流式执行时间线 工作台按事件序号展示任务进度、工具调用和回执。页面刷新、断网重连或任务结束后再打开，都能回读已持久化的事件。
  • 移动端与多端一致 界面会适配软键盘和横幅高度，并处理中文输入法组合态，减少误触。商机看板用版本校验防止多端同时改写时的脏更新。
  • 统一领域服务与异步执行 产品界面与 Agent 运行时共享同一套领域能力，数据层按组织做行级隔离。长任务先落库再入队，由独立 Worker 执行，避免页面超时悬挂。
